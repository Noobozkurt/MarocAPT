# Stuffin3D — 3D asset & digital product store

Next.js 15 (App Router) · TypeScript · Tailwind · React Three Fiber + drei · `<model-viewer>` (AR) ·
PostgreSQL + Prisma · Redis · Socket.IO · Stripe (+ local test payment provider) · NextAuth (password, magic link, OAuth, TOTP 2FA).

> Build status: work in progress — see "Status" below and `docs/FAILURE_REPORT.md` for why the original generated project failed.

## Quick start (local)

Requirements: Node 20.11+, Docker (or local PostgreSQL 15+ and Redis 7).

```bash
cp .env.example .env            # then set NEXTAUTH_SECRET and APP_ENCRYPTION_KEY (openssl rand -hex 32)
docker compose up -d            # postgres, redis, minio, mailpit
npm install
npx prisma migrate deploy       # creates schema + immutable audit-log trigger + trigram search indexes
npm run db:seed                 # users, 20 generated CC0 models, prices, orders, chats, help center
npm run dev                     # http://localhost:3000  (Next + Socket.IO + job worker in one process)
```

### Payments

- **Without Stripe keys** the app uses a local *test provider*: checkout redirects to `/pay/test/...`, and the "provider" sends a **signed** `checkout.session.completed` webhook to `/api/webhooks/test`. Orders are fulfilled only from that verified webhook — exactly like Stripe. Test cards: `4242 4242 4242 4242` (success), `4000 0027 6000 3184` (3-D Secure), `4000 0000 0000 0002` (declined).
- **With Stripe**: set `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`, then forward webhooks locally:
  ```bash
  stripe listen --forward-to localhost:3000/api/webhooks/stripe
  ```
  Handled events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `payment_intent.succeeded`, `charge.refunded`, `charge.dispute.created`, `checkout.session.expired`. Every event is stored by id (idempotent; duplicates are acknowledged without side effects).

## Architecture

```
server.ts               Custom server: Next.js + Socket.IO (Redis adapter when REDIS_URL is set) + DB job worker
prisma/schema.prisma    Full data model (users/RBAC, catalog, versions/files, licenses, orders, refunds, disputes,
                        webhooks, coupons, bundles, reviews, chat, notifications, audit log, jobs, settings)
prisma/seed.ts          Seed; models are generated by scripts/models.ts (CC0, built with three.js + glTF-Transform)
src/lib/                env, auth (NextAuth), session guards, permissions (RBAC), TOTP, crypto, tax, pricing, licenses,
                        rate limiting, email, sanitisation, i18n (EN/FR)
src/server/             catalog/search, cart quotes, checkout, payments (stripe/test), fulfilment & refunds,
                        downloads (single-use signed grants), PDFs (invoice, certificate), chat core, socket server,
                        presence, malware scan, job queue, glTF pipeline (inspect, decimate, meshopt), storage (local/S3)
src/app/(store)/        Storefront, product pages, cart, checkout, account area, support chat
src/app/admin/          Admin panel (in progress)
src/middleware.ts       Nonce-based CSP, security headers, /admin + /account gate (2FA enforced for staff)
```

Key guarantees implemented:
- **Permissions are enforced server-side** (`requirePermission` / `requirePagePermission`), never by hiding UI. Staff need a 2FA-verified session.
- **Audit log is append-only at the database level** (trigger rejects UPDATE/DELETE/TRUNCATE).
- **Downloads**: ownership check → single-use token (stored as SHA-256) valid `DOWNLOAD_URL_TTL_SECONDS` (default 300 s) → re-checked on use; per-license download limits, rate limits and a download log. Refunds/chargebacks revoke licenses and push `library:updated` to the customer's open tabs.
- **Tax**: EU VAT per member state (OSS), B2B reverse charge only with a VIES-validated VAT ID in another member state, UK VAT, US state sales tax on digital goods, sequential invoice numbers.
- **Chat**: messages persisted in Postgres, dedup on `clientMessageId`, ACK with real id, broadcast via Socket.IO rooms (Redis pub/sub across instances), reconnect catch-up, cursor pagination, typing (auto-expire), read receipts from read pointers, attachment malware scanning before agents can see files, rate limits, spam/profanity filter, offline email digests with reply-by-email threading, CSAT, retention/anonymisation.
